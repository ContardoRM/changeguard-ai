# ChangeGuard AI — Change Review Requirements

## Purpose

ChangeGuard AI is a local, reproducible AI Change Review Board for Terraform. It demonstrates Kiro Crew orchestration, specialized agents, human approval, hooks, and spec-driven development without requiring an AWS account, LocalStack, Docker, or deployed infrastructure.

## Scope

The MVP supports exactly three change scenarios and four rule IDs.

### Security

- `SEC-001`: TCP port 22 changes from a non-public CIDR to `0.0.0.0/0`.
- `SEC-002`: TCP port 5432 changes from a non-public CIDR to `0.0.0.0/0`.

### Reliability

- `REL-001`: an `aws_ecs_service` changes from `desired_count >= 3` in the baseline to `desired_count = 1` in the candidate.

### Blast Radius

- `BR-001`: an `aws_db_instance` changes from `deletion_protection = true` in the baseline to `false` in the candidate.

No additional infrastructure policies are part of the MVP.

## R1 — Real Terraform evidence

WHEN the demo baseline is prepared,
THE SYSTEM SHALL run real Terraform commands locally and write a Terraform plan JSON file to `artifacts/baseline-plan.json`.

WHEN a review begins,
THE SYSTEM SHALL run real Terraform commands locally and write the candidate plan JSON to `artifacts/candidate-plan.json`.

Terraform execution SHALL use `-refresh=false` and SHALL NOT execute `terraform apply` or `terraform destroy`.

## R2 — No AWS account dependency

THE SYSTEM SHALL NOT require real AWS credentials, an AWS account, LocalStack, Docker, or deployed infrastructure.

THE SYSTEM MAY require internet access during the initial `terraform init` if the AWS provider is not already cached.

## R3 — Baseline comparison

THE SYSTEM SHALL NOT infer historical `before` values from a fresh Terraform state.

THE SYSTEM SHALL compare values from `artifacts/baseline-plan.json` with values from `artifacts/candidate-plan.json` to identify supported changes.

## R4 — Independent specialist review

THE SYSTEM SHALL delegate Security review to a read-only Security Reviewer agent.

THE SYSTEM SHALL delegate Reliability and Blast Radius review to a read-only Reliability Reviewer agent.

WHEN possible, both reviewers SHALL execute in parallel.

## R5 — Strict findings

THE Security Reviewer SHALL report only `SEC-001` and `SEC-002`.

THE Reliability Reviewer SHALL report only `REL-001` and `BR-001`.

IF evidence is insufficient to prove a supported transition,
THE reviewer SHALL NOT invent a finding.

## R6 — Human approval

WHEN one or more supported findings exist,
THE SYSTEM SHALL report `CHANGE_BLOCKED` and SHALL pause before modifying Terraform.

THE SYSTEM SHALL show the rule ID, affected resource, baseline value, candidate value, and proposed remediation.

THE SYSTEM SHALL NOT modify `terraform/main.tf` until a human explicitly approves the remediation.

IF approval is denied,
THE SYSTEM SHALL leave Terraform unchanged and report `REMEDIATION_REJECTED`.

## R7 — Deterministic remediation

WHEN remediation is approved,
THE Remediator agent SHALL invoke only the deterministic local remediation script.

THE remediation script SHALL modify only the supported unsafe value in `terraform/main.tf`.

The LLM SHALL NOT perform arbitrary HCL rewrites.

## R8 — Re-verification

AFTER remediation,
THE SYSTEM SHALL generate `artifacts/remediated-plan.json` using real Terraform commands.

THE Security Reviewer and Reliability Reviewer SHALL compare the baseline plan with the remediated plan.

THE SYSTEM SHALL report `SAFE_TO_SHIP` only if Terraform succeeds and both reviewers return `PASS`.

## R9 — Hook safety invariant

A Kiro hook SHALL prevent any tool command containing `terraform apply`, `terraform destroy`, or an AWS CLI invocation from being used by the remediation flow.

## R10 — Judge experience

A judge SHALL be able to evaluate one complete scenario with a workflow equivalent to:

1. clone repository;
2. run setup/baseline;
3. inject one supported change;
4. run Kiro Crew review;
5. observe specialist findings;
6. approve remediation;
7. observe a second real Terraform plan and final verdict.

The intended evaluation time is approximately five minutes.

## Acceptance Criteria

- Baseline, candidate, and remediated evidence are generated by Terraform.
- No AWS API call or deployment is necessary.
- Review agents are independent and read-only.
- Remediation requires human approval.
- Remediation is deterministic and narrow.
- No external Python dependency is required.
- All three demo scenarios are reproducible.
